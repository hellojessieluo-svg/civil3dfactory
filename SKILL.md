# civil3dfactory

Repository: `{{C3DF_ROOT}}` (all paths below are relative to it). Entry point: `civil3dfactory.ps1`.
A task JSON goes in, a result JSON comes out; accoreconsole (Civil 3D's headless core) does the work.

## Install

If `{{C3DF_ROOT}}\civil3dfactory.ps1` does not exist:

```powershell
git clone https://github.com/hellojessieluo-svg/civil3dfactory.git
powershell -ExecutionPolicy Bypass -File civil3dfactory\install.ps1
```

`install.ps1` detects Civil 3D 2022-2027, installs the prebuilt engine bundle (downloaded from the release), fetches the two exe tools, installs this skill and the four specialised skills into the agent skill folders, and runs a read-only self-check on `examples\channel-demo.dwg`.
Restart Civil 3D once if it was open. The only thing that can be missing is Civil 3D itself.

## Strategy

**L1 view -> L2 op -> L3 exe.** Reconnaissance first, always:

```powershell
civil3dfactory.ps1 -Dwg <file.dwg> -View outline     # surfaces, alignments, profiles, corridors, assemblies (PKT status), sample line groups, views, blocks, layers
civil3dfactory.ps1 -Dwg <file.dwg> -View issues      # broken references, empty results, PKT not embedded, sample lines without corridor source
```

Object and style names come from `outline` / `civil_env` / `list_styles`, never from guessing. After a change run `-View issues` again; `-View screenshot` gives a PNG.

## Help system

When unsure about an op's parameters run help instead of guessing:

```powershell
civil3dfactory.ps1 -Help                 # every op, one line: * writes the drawing, + has a contract
civil3dfactory.ps1 -Help create_corridor # description, parameter notation, contract (inputs / parameters / outputs / effect), example from examples/
```

The catalog is generated by the engine at run time (cached per build), so it is always the truth for the installed version.
Parameter notation: `name(required) other?(default 5)` - a trailing `?` means optional.

## How to call

```powershell
civil3dfactory.ps1 -Dwg <file.dwg> -Ops list_alignments                         # one op, no parameters
civil3dfactory.ps1 -Dwg <file.dwg> -Ops 'set_scale name=1:500'                  # op + key=value pairs
civil3dfactory.ps1 -Dwg <file.dwg> -Task task.json -Result result.json          # task file: use it for anything with nested parameters
civil3dfactory.ps1 -Dwg <file.dwg> -Task task.json -Resident                    # resident accoreconsole, skips the 6 s cold start
```

Task JSON: `{ "ops": [ { "op": "create_profiles", "alignment": "C1", "surface": "EG", "design_elev": 3.0 }, { "op": "save_dwg", "out": "<absolute path>/out.dwg" } ] }`.
`{{C3DF_ROOT}}` and `{{DWG_DIR}}` inside a task file expand to the repository / drawing folder. Write task files with a script or an editor, not by
quoting JSON on the PowerShell command line.

Result JSON: `{ "ok": bool, "ops": [ { "op", "ok", "data" | "error" + "stack", "ms" } ], "timing" }`, written to `-Result` (default: next to the drawing) and echoed.
Read `ok` per op and look at `data`: an op that succeeded with zero sections, zero volume or an empty list is a failure to investigate, not a success.

Resident mode: `-Resident` keeps one accoreconsole per drawing alive (idle timeout 600 s); the in-memory state carries over between calls.
`scripts\resident.ps1 -Action status|stop|reload -Dwg <file.dwg>` manages it. `dirty: true` in the status means unsaved changes.

## Three rules that cause rework

1. **Nothing is saved unless you say so.** Every op changes memory only. End a task with `{"op":"save_dwg","out":"<absolute path>","overwrite":true}`.
   accoreconsole cannot overwrite the drawing it opened, so `out` is always another file; the demo drawings are never modified.
2. **Plotting renders plain AutoCAD only.** Section views, profile views and other Civil objects come out as an empty page without an error.
   Plot pure-CAD drawings (the title-block demo, or a drawing exported to plain AutoCAD) - see the plot skill.
3. **Placing blocks is an op, filling attributes is the exe.** Title blocks are inserted with `insert_title_blocks` / `create_block_definition`;
   their values are rewritten with `DWGAttributeEditor.exe` (export JSON -> edit values -> update) or the `set_block_attributes` op.

## L1: view modes

| Mode | What you get |
|---|---|
| `outline` | drawing info, surfaces, alignments, profiles per alignment, corridors (baselines, regions, assemblies, surfaces), assemblies with subassembly status, sample line groups (sources, material lists), section / profile views, blocks, used layers |
| `stats` | entity counts by type and layer, surface statistics, corridor statistics |
| `issues` | list of `{level, code, object, message}`: missing profiles, regions without assembly, PKT status not UpToDate, empty corridor surfaces, sample lines without corridor source, groups without material list |
| `screenshot` | PNG of the model space (`-Out <png>`, `window`, `width`) rendered by the Civil 3D kernel |

Quantities: `create_sample_lines` `compute_quantities` `export_material_volumes` `export_quantities` `rebind_volume_tables`

Sheets and blocks: `create_block_definition` `insert_title_blocks` `dump_block_attributes` `set_block_attributes` `plot_pdf` `export_to_autocad` `arrange_section_sheets` `create_sheet_region` `create_plan_frames_from_alignment` `create_plan_layouts_from_frames`
Read-only: `view` `civil_env` `drawing_info` `list_surfaces` `list_alignments` `list_profiles` `list_styles` `list_blocks` `list_layers` `list_civil_views` `corridor_stats` `surface_stats` `dump_corridor_params` `dump_material_styles` `dump_label_styles` `api` `snoop`
Persistence: `save_dwg`

The full list (140+) is `civil3dfactory.ps1 -Help`; there is no catalog file to read.

## L3: exe tools

- `tools\dwg-attribute-editor\DWGAttributeEditor.exe --headless-export <folder|dwg> <out.json> [--block TITLE]` / `--headless-update <folder|dwg> <in.json>` - title block attributes as JSON and back (backups kept).
- `tools\dwg-titleblock-plotter\DWGTitleblockPlotter.exe <folder|dwg> [outdir] [--block TITLE] [--color]` - one A3 PDF per title block reference.
- `tools\pkt-forge\bin\out\PktForge.exe channel|daylight|flatdig ...` - writes a LEFT/RIGHT .pkt subassembly pair offline.

## Specialised skills

Load exactly one per task after this file; it carries the node sequence, parameter sources, example task and acceptance checks.

| Skill | When to use |
|---|---|
| `civil3dfactory-pkt` | a cross-section must become a subassembly / assembly: bottom width, side slopes, bench, lining; PKT repair |
| `civil3dfactory-styles` | how section / profile views, labels, material hatching look: edit the drawing's own styles (or build new ones) and apply them |
| `civil3dfactory-corridor` | the linear model: profiles, corridor, corridor surface, sample lines, quantities, section and profile views, xlsx |
| `civil3dfactory-plot` | plain-CAD sheets with title blocks: rewrite attributes, plot every sheet to PDF, merge |

Capabilities outside these four (area grading, islands, parcels, repairs, plan sheets) exist as ops: find them with `-Help`, no skill promises them.

## Examples

`examples\README.md` lists the two demo drawings (`channel-demo.dwg`: terrain EG, centerlines C1 / C2, assembly C3DF-Channel, a full set of `@C3DF-*` house styles; `title-block-demo.dwg`: three A3 sheets) and the sheet template `sheet-A3.dwt`
and one task file per skill. Every task runs as is: `civil3dfactory.ps1 -Dwg examples\channel-demo.dwg -Task examples\corridor\02-build.json`.
Lookup order for any job: examples -> skills -> `-Help <op>` -> tools. Only when none of them covers it, propose a new op.

## Verify and wrap up

- Every op in the result has `ok: true` and non-empty `data` (sections > 0, volumes != 0, views == sample lines, PDFs == title blocks).
- `-View issues` on the saved copy is `healthy: true` or shows only expected warnings.
- Report the saved file path, the key numbers from the result, and anything you could not verify.

## Compatibility and limits

- Civil 3D 2025 / 2026 tested; 2027 and 2022-2024 compile against their SDKs (2022 lacks a few 2023+ API members: PKT embedding, ImportSACSubassembly). DWG 2018 format throughout.
- Headless (accoreconsole) constraints: the host drawing cannot be overwritten (eFilerError) - use `save_dwg` `out`; AEC tables cannot be exported to plain AutoCAD;
  creating several layouts with viewports in one session can crash - save every 3; **plotting cannot render Civil 3D objects** (2 KB blank PDF, no error) - plot plain-CAD drawings only.
- One resident per drawing, one request at a time; a drawing must never be edited concurrently.
- Text heights in style ops are plotted millimetres; hatch pattern scale is in drawing units.
